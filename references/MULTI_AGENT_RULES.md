# 多 Agent 共同規則管理（2026-08 實戰）

跑多個 Hermes profile／多個 agent 的團隊，規則最容易散落各 agent 記憶、各自解釋。以下架構實測有效，可整組複製。

## 1. 共同規則單一來源

- 共同規則只放**一個共同檔**，分三層：
  - **短核**：沒讀到就會立刻犯錯的最小集（常駐注入每次開工）
  - **索引**：正文有哪些節，按需打開
  - **正文**：完整規則，依索引只讀相關節
- **個人 MEMORY 只留角色專屬**＋會立刻犯錯的操作事實；不把全員規則各抄一份
- 共同檔與個人記憶衝突時，以共同檔為準，並回報管理者

## 2. 按需載入

- 開工只帶：短核＋索引
- 任務初期釐清規格／邊界，或交付前合規自掃：依索引只讀相關節
- 中間執行（寫碼、除錯、查檔、重試）**不要整包重讀正文**

## 3. 規則進化流程

- 使用者明確說「不能做、做得不好、以後不要再」→ **當天**寫進該 agent 長期記憶
- **隔日蒸餾**進共同檔（每日一次，由負責 agent 從對話差異萃取新規則）
- 不要另開第二套共同檔；改規則就改記憶來源，等蒸餾

## 4. 與 Telegram 表格紅線

- 多 agent 共用的輸出格式紅線（表格、rich、streaming）見 `TELEGRAM_RICH.md`，各 agent 共同遵守同一份

## 5. 注意

- 共同檔改動＝改真紅線，需要管理者級裁示；個人事實放各自記憶，不塞共同檔
- 公開 repo 只提供**架構與原則**，不綁任何組織名稱或特定共同檔內容
